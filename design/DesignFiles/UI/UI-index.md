_建立時間：2026-05-01_
_最後更新：2026-05-02_
_狀態：v0.3 補入每項優先度（P0~P4 / Post-Jam）_
_管控者：ux-designer（主體）_

---

## 0. 文件目的

本檔為 The Guild 所有 UI 元素的單一事實來源（Single Source of Truth）。所有 UI 來源由 26 份 GDD（F-01~F-03、C-01~C-06、FT-01~FT-12、P-01~P-03、D-01~D-02）反向推導，並補充劇本（FT-09 v3.1 奧蘿瑞陣營）所需特殊 UI 與通用控件。

**用途**：

1. UI 製作 / 生成的狀態追蹤（5 階段：Spec → Wireframe → Mockup → Asset → Impl）
2. 跨 GDD UI 需求彙整，避免重複設計與遺漏
3. 為 P-02 Main UI Framework GDD §3 各面板填寫提供範圍依據
4. 為 art-director / character-designer / unity-ui-specialist 提供工項清單
5. **每項資源含獨立規格（尺寸 / 格式 / 變體 / 9-slice / atlas）與優先度（P0~P4 / Post-Jam）**

## 1. 命名規則

### 1.1 UI ID 格式

```
{層代碼}-{兩位數} 或 {層代碼}-{子層}-{兩位數}
```

| 層代碼 | 意義 |
|---|---|
| `A-` | Scene 場景層 |
| `B-` | In-Scene UI 場景內嵌 |
| `C-` | Always-on HUD 常駐覆蓋 |
| `D-` | Main Panel 主面板 |
| `E-` | Modal Popup 模態彈窗 |
| `F-A` ~ `F-H` | 原子素材子層 |

範例：`D-01`（委託板）、`E-05`（訃聞畫面）、`F-C-08`（紙條 light 版）

### 1.2 個別 UI Spec 檔命名

```
design/UI/【{UI-ID}】{ui-name}.md
```

例：`design/UI/【D-01】commission-board.md`、`design/UI/【F-C-01】dialogue-bubble-character.md`

### 1.3 UI 美術資產命名

```
Assets/Art/UI/{Category}/{UI-ID}_{variant}.png
```

例：`Assets/Art/UI/Panel/D-01_default.png`、`Assets/Art/UI/Bubble/F-C-08_light.png`

## 2. 狀態圖例（5 階段）

| 階段 | 圖示意義 | 產出形式 | 主負責角色 |
|---|---|---|---|
| **Spec** | UI 個別規格書（互動、版型、狀態機、文案 key 列表） | `design/UI/【{ID}】*.md` | ux-designer |
| **Wireframe** | 低保真線框圖（手繪或 ASCII / 文字版型描述） | 圖檔 / 文字 | ux-designer |
| **Mockup** | 高保真視覺稿（含色彩、字型、構圖） | Midjourney / SD 產圖 | art-director |
| **Asset** | 最終美術素材入庫（atlas、sprite、9-slice） | `Assets/Art/UI/` | art-director / character-designer |
| **Impl** | Unity UI Toolkit (UXML/USS) 實作通過 EditMode/PlayMode 測試 | Unity 場景 + 代碼 | unity-ui-specialist |

| 圖示 | 意義 |
|---|---|
| ✅ | 完成 |
| 🔧 | 進行中 |
| 📐 | 規劃中（已排入工項） |
| ⬜ | 未啟動 |
| ⚠️ | Post-Jam（Jam 範疇外） |
| ➖ | 不適用（如 atomic asset 不需 wireframe） |

**進度欄位簡寫**：每項 UI 進度以 5 位元連寫，順序 `Spec / Wire / Mock / Asset / Impl`。例 `⬜⬜⬜⬜⬜` = 全未啟動；`✅✅⬜⬜⬜` = Spec 與 Wireframe 完成、其餘未啟動。

## 3. UI 分類框架（六層）

| 層 | 名稱 | 渲染層級 | 是否阻塞輸入 | 範例 |
|---|---|---|---|---|
| **A** | Scene 場景層 | 最底層 | 否（穿透） | 公會橫幅景觀、可互動場景物件 |
| **B** | In-Scene UI | Scene 之上 | 否 | 金幣顯示、破產倒數、頭頂狀態 |
| **C** | Always-on HUD | In-Scene 之上 | 否（局部 hit area） | 設定按鈕、Log 入口、劇情指示器 |
| **D** | Main Panel | HUD 之上 | 部分（panel 內部接收輸入） | 委託板、名冊、建設、面試 |
| **E** | Modal Popup | Main Panel 之上 | 是 | 啟動畫面、訃聞、確認彈窗 |
| **F** | Atomic Asset | 跨層 | — | 圖示、字型、立繪、按鈕、氣泡框 |

**Z-order（由低至高）**：A < B < C < D < E < （F 依 host 容器決定）

## 3.5 共用規格預設（Default Specs）

除非個別項目另行標示，所有 UI 資源預設遵守：

| 項目 | 預設規格 |
|---|---|
| **格式** | PNG-24 + Alpha (RGBA) |
| **色彩空間** | sRGB |
| **色彩深度** | 8-bit / channel |
| **背景** | 透明（除 A-01 場景背景外）|
| **禁用色** | `#000000`（透明色鍵保留；需要黑色時用 `#0A0A0A` 以下色階）|
| **9-slice** | 所有可拉伸元件（按鈕、面板、對話框）必須 9-slice 設計 |
| **Atlas padding** | 圖示集留 2px 透明邊距，避免 sampler 抓鄰像素 |
| **Pixel Art 設定** | 整數倍縮放友善（不使用反鋸齒插值的中間色）|

**規格欄位語法**（用於 §4 各表）：

```
{尺寸 px} / {變體數與名稱} / {特性 token}
```

特性 token 縮寫：
- `9-slice` — 可拉伸 9 切片
- `atlas` — 放入 sprite atlas
- `tile` — 可水平／垂直 tile
- `seq` — sprite sheet 序列幀
- `font` — 字型檔（TTF/OTF）
- `dyn` — 動態尺寸（自動寬或自動高）
- `over` — 覆蓋全螢幕／全窗
- `非PNG` — 特殊格式註明

格式特例會顯式標註（如 `TTF`、`Sprite Sheet`）。

## 3.6 優先度定義（Priority Levels）

| 優先 | 含義 | 對應對象 |
|---|---|---|
| **P0** | 場景底層與基礎元件，必須最先完成 | A 場景層（A-01~A-13）、B 場景內嵌（B-01~B-05）、F-A 通用控件、F-B 主要氣泡、F-C 主要圖示、F-F 字型 |
| **P1** | MVP 核心循環必要 UI；玩家第一次進遊戲就會用到 | 委託板 / 名冊 / 公會總覽 / 結算視窗 / Log / 啟動畫面 / 公會建立 / 通用確認彈窗 / 金幣聲望顯示 |
| **P2** | 深度系統 UI；MVP 通過後依序補完 | 場景層 / 常駐 HUD / 建設 / 職員 / 面試 / 設定 / 離線摘要 |
| **P3** | 敘事與動畫；劇情系統與美術潤飾 | 故事面板 / 訃聞 / Game Over 結算 / 立繪 / 紙條三版 / 動畫元件 |
| **P4** | 最終補強；空狀態與 fallback | 空名冊 / 空 Log / 通用錯誤回退 |
| **⚠️** | Post-Jam（Jam 範疇外）| 場景轉場 / 職員氣泡 / 教學引導 |

**排序原則**：

1. 依賴方向：原子素材（F-A/F-B/F-C/F-F）先於面板（D/E）
2. 引用面密度：被多個面板引用的元件優先（如 F-A-07 主要按鈕）
3. 玩家觸達順序：首次遊玩必經路徑（E-04 公會建立 → D-01 委託板 → D-08 結算）優先
4. 風險：技術紅線項（如 P-01 透明窗相關）優先

## 7. 維護指引

1. **新增 UI 項目**：先在本 index 登記，分配 ID，標記 owner GDD、規格、優先度
2. **狀態變更**：完成某階段後立即更新對應位元（5 位元連寫），並刷新 §5 統計
3. **規格調整**：任何尺寸 / 變體 / 9-slice / atlas 變更須同步更新本檔規格欄位 + brief §3.3 對應行
4. **優先度調整**：依專案進度可動態調升降；調整時於 §8 變更歷史登記理由
5. **個別 Spec 撰寫**：spec 完成後路徑寫入「備註」欄
6. **重大重構**：在 §8 變更歷史登記日期與摘要
7. **避免在此 index 內寫詳細互動規格**：互動細節寫在個別 spec 檔，本 index 僅作為總目錄與規格表
